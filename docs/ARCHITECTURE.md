# Architecture

`src/content.ts` defines the canonical nine spreads and eight turning leaves. A leaf's front is the current right page and its reverse is the next left page. Startup assertions and the model check validate that mapping.

`src/artwork.ts` draws colorful stick figures, pencil comic panels, speech bubbles, titles, paper and cloth textures, and application worksheets into page canvases. Each domain has a distinct figure color; the final spreads bring those figures together. Font weight and style are placed before the pixel size so canvas titles retain their intended size. Shared profile data and finale summaries are passed from the application layer. System fonts and procedural drawings require no remote font or image loader.

`src/main.ts` owns the scene, two resting pages, an explicitly grouped front/reverse turning sheet, a thick cover box with separate front, back, and cloth edge materials, book hardware, camera, and input state. Interior sheet positions integrate a curved tangent to preserve paper length; the hard cover rotates as a rigid box. Either closed cover remains visible in place of the thin resting page. The back cover closes on the left, hides the right stationary book half, and reopens into the finale. A spring uses small integration steps for consistent timing across display refresh rates. When a sheet lifts, its source page is replaced by the next underlying page. The spread changes only when the sheet settles. During the cover turn, the left stationary group is hidden so there is no duplicate flat sheet left behind.

Navigation keeps one destination and replaces it when another chapter is selected. Mobile reading moves the camera between page sides. Neighboring page textures are warmed after settling and cached around the current spread. Without WebGL, the same texture canvases are painted into a book with a CSS rotation for the moving sheet.

Application forms and expanded comic pages use DOM dialogs with keyboard focus handling. Domain answers use the existing `acm-sketchbook-applications-v2` storage key. Name, registration number, email, and year live once in `acm-sketchbook-profile-v1`; older drafts provide a profile migration source. Domain forms and exports always read that shared profile. The cover nameplate expands into the profile editor, and profile edits refresh the cover and affected page previews. Draft changes refresh the corresponding worksheet and finale preview after a short debounce. Reading position and bookmark use a separate `acm-sketchbook-reading-v1` key. Application data stays local and JSON export provides a portable copy.

`src/style.css` styles the reader controls, dialogs, reading progress, and fallback book. The automated checks in `scripts/` cover the page model, motion, and content without requiring a browser renderer; see `docs/QA.md` for their limits.
